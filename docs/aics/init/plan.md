## Risk Coverage

- R1 (a stray write replaces a root link): INIT-1 fixes the one arcdlc writer; INIT-7 ships `make -C docs check` and tells the hub guide to run it when the registry looks wrong.
- R2 (a new skill fails the CI pins or never installs): INIT-6 adds `init` to `bundle.Skills` and `SUBSKILLS` in the same commit as the skill file; INIT-9 updates the four CI loops and the manifests.
- R3 (bundle version skew across machines sharing a hub): INIT-7 records the minimum `arctool` version in the hub guide template and makes `init` check `arctool version` before writing workspace rules.
- R4 (a push retry loop): INIT-3, one fast-forward and one retry, then `BLOCKED` with the git error.
- R5 (migration on a dirty repository): INIT-8 refuses to start on any repository whose `git status --porcelain` is not empty.
- R6 (a moved plan with paths that cannot be found): INIT-8 reports every unprefixed path per task and names `/arcdlc:plan <slug>` as the next step for that plan.
- R7 (a harness with no guide because a link is missing): INIT-7, four links, `check`, and a first line in the hub `README.md` template for a reader at the root.
- OQ1 (a root that is itself a repository holding repositories): INIT-6, `init` names the case and stops. No layout is scaffolded for it.
- OQ2 (which branch the migration commit lands on when a repository is not on its default branch): INIT-8, `init` asks per repository, one question per turn.
- OQ3 (converting MetricAid's `Repo:` lines inside `WHERE`): accepted, not covered. The migration step is for per-repository folders, not for an existing hub; that rewrite is MetricAid's call.
- OQ4 (`sync` run inside the hub writes `_none_`): accepted, not covered. A separate small `arctool` guard, out of this initiative's scope by the AIC.
- Routing (a skill description nobody can test in CI): process mitigation. INIT-9 adds the `init` rows to `docs/routing-checks.md`; the engineer re-runs that file by hand after the release, as `AGENTS.md` requires for every description change.

### INIT-1: Make `arctool sync` write through a symlink and base links on the real file

- WHAT: Resolve a symlinked registry target before the atomic rename, and write each registry link relative to the real file's directory, so a root link into a hub is preserved and the hub's own `AGENTS.md` links read `aics/<slug>/aic.md`.
- HOW:
  In `internal/registry`, add `func Rebase(inits []Initiative, base string) []Initiative` that returns a copy whose `DocRelPath` is rewritten with `filepath.Rel(base, abs)` and `filepath.ToSlash`, where `abs` is the working directory joined with the current `DocRelPath`; an `Initiative` with an empty `DocRelPath` is copied unchanged. In `runSync` (`cmd/arctool/main.go`), for each target: `os.Lstat` it; when it is a symlink, `filepath.EvalSymlinks` it and use the resolved path for `Preview` and `WriteFile`, and a dangling link is an error printed as `arctool: <target> is a symlink to a missing file` with exit 4; then call `Rebase(inits, filepath.Dir(resolvedAbs))` and pass the result. A target that is not a symlink is resolved to its absolute path and rebased the same way, which yields today's `docs/aics/<slug>/aic.md` unchanged when the target sits in the working directory. `--check` uses the same resolution and still writes nothing. `Render`, `Splice`, `Preview`, `WriteFile` and `atomicWrite` keep their signatures. Bump `const version` in `cmd/arctool/main.go` to `0.20.0` and add one line to the `sync` entry of the usage text: `a symlinked target is written through, and links are relative to the real file`. Out of scope: any change to `scanInitiatives`, `resolvePlan` or `aicsDir` (ADR-0001, ADR-0026), and a guard for `sync` run with no `docs/aics/` (AIC OQ4).
- WHERE:
  Layer `registry`: `internal/registry/registry.go` (add `Rebase`).
  Layer `cli`: `cmd/arctool/main.go` (`runSync`, `version`, `usage`).
  Tests: `internal/registry/registry_test.go` (`TestRebase`: a base one level below the working directory yields `aics/pay/aic.md`; a base equal to it yields `docs/aics/pay/aic.md`; an empty `DocRelPath` stays empty), `cmd/arctool/main_test.go` (`TestRunSyncThroughSymlink`: a temp root holding `docs/` as a directory with `docs/aics/pay/aic.md` and `docs/AGENTS.md`, plus `AGENTS.md` at the root as a symlink to `docs/AGENTS.md`; after `runSync` the root entry is still a symlink per `os.Lstat`, `docs/AGENTS.md` holds `- [Payments](aics/pay/aic.md)`, and a second run reports no change; `TestRunSyncDanglingSymlink`: exit 4 and nothing written).
- WHY: Today the rename replaces a root symlink with a regular untracked file and the tracked hub copy goes stale, which is why the one team running a hub bans the command and hand-edits the registry (AIC H7, R1).
- Acceptance:
  - GIVEN the temp tree in `TestRunSyncThroughSymlink` WHEN `runSync` runs THEN `os.Lstat(root/AGENTS.md)` reports a symlink, `docs/AGENTS.md` contains `- [Payments](aics/pay/aic.md)`, and a second run returns 0 with `already up to date`.

  - GIVEN the change WHEN `arctool version` runs THEN it prints `arctool 0.20.0`, and `gofmt -l .` prints nothing and `go vet ./...` is clean.

### INIT-3: Add the workspace per-task contract to `/arcdlc:execute`

- WHAT: Teach `/arcdlc:execute` to detect a workspace, read the task's `Repo` key first, make the code commit in that repository and the status commit in the hub, push the hub after every status write with one fast-forward retry, and never push a product repository.
- HOW:
  Add a section `## In a workspace` to `skills/execute/SKILL.md` directly after `## Tooling: prefer arctool`, and reference it from the per-task contract steps 2, 6 and 7. Detection, once per run: the working directory is not a git work tree and `git -C docs rev-parse --show-toplevel` resolves to `<cwd>/docs`. The hub's default branch is the short name of `git -C docs symbolic-ref refs/remotes/origin/HEAD`, or the current branch when that ref is missing. Rules: (1) the task's `extra.Repo` from `arctool next --json` (fallback: the `- Repo:` line) names the one repository to change; a workspace task with none is blocked with `arctool block <id> -m "no Repo key; plan defect"`. (2) Every `arctool` status write happens in the hub, so `take`, `done`, `block`, `todo` are followed by a hub commit: `git -C docs add docs/aics/<slug>/plan.md` is wrong because paths are hub-relative, so the command is `git -C docs commit -m "chore(<slug>): mark <TASK-ID> <STATUS>" -m "Refs: <TASK-ID>" -m "#AI-assisted" -- aics/<slug>/plan.md`, then `git -C docs push origin <default>`. (3) The code commit is made in `<Repo>` on the branch shape that repository's own `AGENTS.md` sets, with the Conventional Commits message from this skill and `Refs: <TASK-ID>`; when the repository's guide says nothing, the existing trunk-based short-lived task branch applies. A `Repo: docs` task makes one hub commit holding both the change and the status. (4) Order within a task: `take` plus hub commit and push; implement and commit in `<Repo>`; `done` plus hub commit and push. (5) A rejected non-fast-forward hub push is retried exactly once after `git -C docs pull --ff-only origin <default>`; a fast-forward that fails, or a second rejection, blocks the task with the git error verbatim as the reason and ends the run. (6) A product repository is never pushed by a run; the report lists each repository with unpushed commits. (7) The spawn prompt names the task's repository and these rules, and the subagent runs tests and lint with that repository's documented commands from inside it. (8) The Verification phase part 2 runs build, test and lint in every repository named by a `Repo` key of a `DONE` task, and part 1 also checks `git -C docs status --porcelain` is empty and `git -C docs log origin/<default>..HEAD` is empty. Amend the existing "Do not push" sentence in step 6 to "Do not push a product repository; in a workspace the hub is pushed after every status commit, see `## In a workspace`". Out of scope: parallel runs (ADR-0024), the `Repo` key definition (INIT-2), and the other skills' hub-write paragraph (INIT-4, INIT-5).
- WHERE:
  Layer `skills`: `skills/execute/SKILL.md`.
  Tests: `internal/bundle/bundle_test.go` (existing `TestBundleIsConsistent`, must still pass).
- WHY: `plan.md` and the code live in different repositories in a workspace, so the one-commit contract cannot hold, and pushing the hub at once is what makes two runs colliding on one task visible immediately (AIC H6, R4).
- Acceptance:
  - GIVEN `skills/execute/SKILL.md` WHEN `grep -n '^## In a workspace' skills/execute/SKILL.md` runs THEN it prints one line placed before `## Initiative selection`.
  - GIVEN the section WHEN read THEN it states each of the eight numbered rules above, and `grep -c 'pull --ff-only' skills/execute/SKILL.md` prints at least 1 and `grep -c 'never pushed' skills/execute/SKILL.md` prints at least 1.
  - GIVEN the per-task contract step 6 WHEN read THEN it no longer says only "Do not push" and points at `## In a workspace`.
  - GIVEN the change WHEN `go test ./internal/bundle/` runs THEN it passes, and the `## Talk simple, write like a human` and `## Judge by the four virtues` blocks are byte-identical to `skills/aic/SKILL.md` per the `awk` extraction in `.github/workflows/ci.yml`.
